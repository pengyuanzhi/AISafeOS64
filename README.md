# AISafeOS64

AISafeOS64 (AI-Generated, Safety-Certifiable, Native 64-bit RTOS) 是一个面向安全关键嵌入式系统的**微内核实时操作系统**，采用细粒度能力（Capability）访问控制模型，以 IPC 为核心通信机制，内核代码量控制在 50KB 以内。

## 设计理念

| 原则 | 说明 |
|------|------|
| **最小内核** | 内核仅提供线程调度、IPC、虚拟内存、中断路由、能力管理五项基本机制 |
| **全新设计** | 从零构建（Clean-slate），不依赖传统操作系统架构，无历史包袱 |
| **IPC 为中心** | 所有服务间通信基于消息传递（同步 Send/Receive/Reply + 异步 Pulse/Notification） |
| **细粒度能力模型** | 内核对象通过能力引用访问，精确控制读/写/执行/转发/撤销等权限，支持传递自动降权 |
| **用户态服务** | 驱动、文件系统、网络协议栈、进程管理等全部运行在用户态 |
| **故障隔离** | 任何用户态服务崩溃不影响内核和其他服务 |
| **硬实时优先** | 确定性调度、低延迟中断处理、最小化不可抢占区 |
| **可验证性** | 设计时即考虑形式化验证潜力，关键组件可数学证明 |
| **混合语言** | 内核纯 C（MISRA C:2012 合规），用户态服务可选 Rust（编译期内存安全） |

### 能力模型

内核对象（线程、端点、页帧、通知对象、设备、中断）通过能力引用访问：

- **细粒度权限控制**：每个能力携带精确的访问权限掩码（读/写/执行/转发/撤销）
- **传递自动降权**：能力传递时权限只能降低，不能升级（delegation with attenuation）
- **可撤销**：支持能力撤销（Revocation），撤销后所有派生访问立即失效
- **CSpace 隔离**：每个进程拥有独立的能力空间，互不干扰

### IPC 通信

| 通信方式 | 特点 | 适用场景 |
|----------|------|----------|
| 同步消息（Send/Receive/Reply） | 阻塞式，强类型 | 客户端-服务器请求 |
| Pulse 异步消息 | 非阻塞，携带优先级 | 中断通知、定时器回调 |
| Notification | 轻量级信号通知 | 事件唤醒 |
| 共享内存 | 零拷贝，大块数据 | 图像/音视频传输 |

### 调度器

- **256 级优先级**：4×64 位位图 + CLZ 指令，O(1) 查找
- **多种策略**：SCHED_FIFO（抢占）、SCHED_RR（轮转）、SCHED_EDF（截止时间）、SCHED_SPORADIC（偶发）
- **多核支持**：1-8 核心 SMP，自动负载均衡，核心亲和性绑定
- **确定性调度**：ARINC 653 分区调度、时间触发调度（TTS）、WCET 预留
- **优先级反转防护**：优先级继承协议 + 优先级天花板协议

### 安全机制

- **地址空间隔离**：独立地址空间 + MMU 页表隔离
- **代码完整性保护**：代码页只读（RX 权限）、ELF 签名验证（ECDSA-P256 + SHA-256）
- **数据执行保护（DEP）**：数据页不可执行
- **ASLR**：地址空间布局随机化
- **栈保护**：Stack Canary + MPU 保护页
- **安全启动链**：硬件信任根 → 引导签名验证 → 内核签名验证 → 运行时完整性度量
- **最小权限**：默认无权限，所有访问必须通过能力显式授权

### 用户态驱动

驱动运行在用户态，通过能力模型安全访问硬件资源：

- InterruptAttach/InterruptWait：用户态中断处理
- MMIO 映射：通过能力授权的设备寄存器访问
- DMA 管理：安全的 DMA 传输
- 资源管理器框架：设备路径注册与访问控制

| 内核数据大小 | < 100KB | 内核数据段 |
| 最小内存占用 | < 1MB | 完整启动内存 |

## 工程实践

### 代码质量保证

- **MISRA C:2012 零偏差**：内核代码完全合规
- **静态分析集成**：CI/CD 自动执行 MISRA 检查
- **自动化测试**：单元测试 + 集成测试 + 回归测试
- **覆盖率要求**：核心模块 > 80%，安全关键代码 MC/DC > 95%
- **模块化设计**：严格接口定义，模块独立可测试
- **API/ABI 版本管理**：接口变更可追踪

### 混合语言策略

| 组件 | 语言 | 原因 |
|------|------|------|
| 内核 | C（MISRA C:2012） | 认证合规、工具链成熟、可验证 |
| 文件系统服务 | Rust | 编译期内存安全、无 GC、适合 I/O 密集 |
| 网络协议栈 | Rust | 无数据竞争、无空指针、高性能 |
| 安全服务/TEE | Rust | 安全关键、内存安全保证 |
| 进程管理/启动器 | Rust | 复杂状态管理、类型安全 |
| 驱动（可选） | C 或 Rust | 灵活选择 |

## 构建说明

### 前置要求

- **工具链**：aarch64-none-elf-gcc（支持 ARMv8-A）
- **CMake**：>= 3.20
- **构建平台**：Linux、Windows (WSL)、macOS

### 构建步骤

```bash
# 1. 配置
mkdir build && cd build
cmake .. -DCMAKE_TOOLCHAIN_FILE=../cmake/toolchain-arm64.cmake

# 2. 编译
make -j$(nproc)

# 3. 输出
# - build/aisafe64.elf
# - build/aisafe64.bin
# - build/aisafe64.dis
```

### QEMU 模拟

```bash
qemu-system-aarch64 \
  -M virt \
  -cpu cortex-a57 \
  -smp 4 \
  -m 1G \
  -kernel build/aisafe64.elf \
  -nographic \
  -serial mon:stdio
```
