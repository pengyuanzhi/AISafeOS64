# 阶段 1.6: 缓存优化

## 优化目标

提高缓存命中率，减少缓存未命中次数，提升整体性能。

**背景**：
- 当前系统有性能测试结果（见 memory/2026-05-02-5.md）
- 指令缓存未命中可能导致指令取指延迟
- 数据结构对齐不当可能导致缓存行浪费和未命中

---

## 1. 数据结构对齐

### 1.1 对齐规则

**ARM64 架构对齐要求**：
- 字节对齐（8字节）：所有指针、uint64_t、double
- 16字节对齐（cache line）：大量访问的数据结构
- 32字节对齐（performance cache line）：关键热数据

**MISRA C:2012 要求**：
- 结构体对齐：使用 `alignas` 关键字（或 GCC 扩展）
- 指针对齐：检查指针地址是否对齐

### 1.2 需要优化的数据结构

**调度器数据结构**：
- 线程控制块（`thread_t`）
- 调度器队列（`ready_queue_t`）
- 运行队列（`run_queue_t`）

**IPC 数据结构**：
- Channel（通道）
- Endpoint（端点）
- Notification（通知）

**内存管理数据结构**：
- VMA（虚拟内存区域）
- Page Table（页表）
- Slab Cache（缓存）

**性能优化**：
- 热数据结构（频繁访问）
- 频繁修改的数据结构

### 1.3 对齐工具函数

```c
/* 数据对齐检查 */
bool is_aligned_to(const void *ptr, uint64_t alignment);

/* 数据对齐 */
void *aligned_alloc(uint64_t size, uint64_t alignment);

/* 填充对齐 */
uint64_t align_up(uint64_t value, uint64_t alignment);

/* 缓存行对齐 */
#define CACHE_LINE_SIZE  64U
#define CACHE_ALIGN(x)    __attribute__((aligned(CACHE_LINE_SIZE)))
```

## 2. 热数据缓存

### 2.1 热数据识别

**访问模式分析**：
- 高频访问数据：每次调度、每次 IPC 都访问
- 低频访问数据：只初始化时访问一次

**示例**：
- **热数据**：当前运行线程、当前 CPU 就绪队列、当前 IPC 通道
- **冷数据**：VMA 树（只查找）、Slab Cache 列表（低频）

### 2.2 热数据缓存策略

**缓存位置**：
- 线程本地存储（TLS）：每个线程有独立的缓存
- CPU 本地缓存：减少跨核访问

**缓存大小**：
- 小缓存（32 字节）：线程控制块指针
- 中缓存（256 字节）：调度器队列
- 大缓存（1KB）：缓存帧（Cacheline）

### 2.3 热数据缓存 API

```c
/* 热数据缓存操作 */
void hot_data_cache_get(void *data);
void hot_data_cache_put(void *data);
void hot_data_cache_flush(void);
void hot_data_cache_invalidate(void);
```

## 3. 指令缓存优化

### 3.1 指令缓存分析

**问题**：
- 函数调用频繁导致指令缓存未命中
- 过长的函数导致指令缓存未命中
- 过多的分支预测失败导致指令缓存未命中

### 3.2 指令缓存优化策略

**代码组织优化**：
- 拆分长函数为短函数
- 减少函数调用深度
- 减少分支预测失败

**代码布局优化**：
- 频繁调用的函数放在一起
- 减少函数跳跃（call/jump）距离
- 使用内联减少函数调用开销

**缓存预热**：
- 启动时加载热代码到指令缓存
- 定期预热热函数

### 3.3 指令缓存优化 API

```c
/* 指令缓存预热 */
void icache_warmup(void);

/* 指令缓存无效化 */
void icache_invalidate(void);

/* 指令缓存同步 */
void icache_sync(void);
```

**测试方法**：

**测试工具**：
- 性能计数器（PMU）
- 统计：L1 数据缓存未命中、L2 缓存未命中

**测试内容**：

## 7. 风险评估

### 7.1 技术风险

- **对齐风险**：对齐不当可能导致性能下降
- **热数据误判**：误判热数据可能导致缓存污染
- **优化过度**：过度优化可能导致代码可读性下降

### 7.2 缓解措施

- **充分测试**：对齐前后性能对比测试
- **性能监控**：使用性能计数器监控缓存性能
- **渐进式优化**：逐步优化，每次优化后验证效果
- **代码审查**：对齐和优化需要代码审查
