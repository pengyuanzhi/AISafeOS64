# AISafeOS64 软件需求规格说明书 (SRS)

**版本**: 2.0
**日期**: 2026-03-29
**架构**: 微内核（Microkernel）

## 0. 设计参考

AISafeOS64 是一个面向安全关键嵌入式系统的微内核实时操作系统，采用从零构建（Clean-slate Design）设计理念，结合现代操作系统设计的先进理念与工程实践。

### 0.1 核心设计原则

#### 0.1.1 从零构建（Clean-slate Design）

- 从零开始构建：不依赖现有操作系统架构，完全重新设计和实现
- 摆脱传统系统中固有的复杂性和安全隐患
- 更适合应对未来对安全、实时性和可验证性的更高要求

#### 0.1.2 细粒度能力模型（Capability Model）

能力机制比现有的微内核（如 seL4、MINIX 3 等）更加精细。每个能力可以精确控制：

- **对象类型**：内存页、设备、线程、中断等
- **权限级别**：读、写、执行、转发、撤销等
- **权限传递**：支持权限的传递、降权（delegation with attenuation）、撤销（revocation）

### 0.2 工程实践与代码质量

- 采用模块化设计、严格的接口定义、自动化测试、静态分析等手段确保代码质量和长期可维护性
- 注重文档和代码规范，便于团队协作与后续演进
- 内核代码严格遵循 MISRA C:2012 标准，MISRA C 是嵌入式系统中最权威的 C 编程规范之一，主要用于保障代码的安全性和可移植性。目标是达到 MISRA C:2012 完全合规，为后续的功能安全认证打下坚实基础

### 0.3 安全与功能安全目标

| 目标 | 说明 |
|------|------|
| 功能安全认证：ISO 26262 ASIL-D | 汽车行业最高安全等级，用于自动驾驶、智能驾驶辅助系统等关键任务场景 |
| 信息安全认证：Common Criteria EAL5+ | 较高安全等级，可用于政府、国防、金融等对安全性要求极高的领域 |
| 形式化验证潜力 | 设计目标允许未来对关键组件（调度器、IPC、能力管理）进行形式化证明 |

### 0.4 实时性支持

- 支持硬实时工作负载（Hard Real-Time Workloads）
- 硬实时系统的响应时间必须严格满足时限要求
- 支持确定性调度、低延迟中断处理和最小化的不可抢占区
- 适用于工业控制、机器人、航空电子等需要强实时保障的场景

### 0.5 原生虚拟化、进程与 POSIX 支持

AISafeOS64 微内核原生支持虚拟化、进程管理和 POSIX 兼容接口：

- **原生虚拟化**：支持硬件虚拟化扩展（ARM VHE / Intel VT-x），虚拟机创建/销毁生命周期管理，vCPU 调度，虚拟中断注入，二级地址翻译（EPT/NPT）。支持 ARINC 653 分区调度，实现时间/空间隔离的虚拟化分区管理
- **进程管理**：用户态进程管理器（ProcessManager）通过 IPC 揥供服务，支持进程创建/销毁/监控。用户态内存管理器（MemoryManager）管理物理内存分配和虚拟地址空间映射。用户态路径管理器（PathManager）管理设备路径命名空间和服务注册
- **POSIX 兼容**：在用户态兼容层提供基本 POSIX API（pthread、mutex、condvar 等），支持应用移植。微内核自有 IPC 机制（通道-连接模型）优先于 POSIX IPC。POSIX 接口作为 P2 优先级，在用户态兼容层实现

### 0.6 用户态服务语言支持

AISafeOS64 用户态核心组件可选 Rust 语言开发：

- **内存安全**：Rust 在编译期防止空指针、数据竞争等常见错误，非常适合构建高可靠性的用户空间服务
- **无 GC**：无垃圾回收机制，适用于资源受限或实时性强的环境
- **现代语法 + 高性能**：提升开发效率的同时保持运行效率
- **用户空间组件包括但不限于**：文件系统服务、网络协议栈、显示/图形子系统、安全服务（TEE）、进程管理与启动器

### 0.7 AISafeOS64 特性总览

| 特性 | 描述 |
|------|------|
| 架构 | 微内核（microkernel） |
| 目标 | 高安全性、高可靠性、可认证、可验证 |
| 应用场景 | 自动驾驶、工业控制系统、智能终端 TEE、IoT 等 |
| 安全标准 | ISO 26262 ASIL-D（功能安全）、Common Criteria EAL5+（信息安全） |
| 认证目标 | 潜在形式化验证 |
| 实时性 | 支持硬实时（hard real-time） |
| 编程语言 | 内核：C（严格 MISRA C:2012 合规），用户空间：可选 Rust |

## 2. 项目概述

### 2.1 架构定位

AISafeOS64 采用**微内核架构**，内核仅提供最小化机制：

- 线程调度
- IPC 消息传递
- 内存管理（虚拟内存）
- 中断路由
- 能力（Capability）管理

所有其他服务（设备驱动、文件系统、网络协议栈、进程管理等）运行在**用户态**，通过 IPC 通信。

### 2.2 设计哲学

| 原则 | 说明 |
|------|------|
| 最小内核 | 内核代码量 < 50KB，仅提供基本机制 |
| IPC 为中心 | 所有服务间通信基于消息传递 |
| 能力模型 | 基于细粒度能力访问控制 |
| 用户态服务 | 驱动/文件系统/网络运行在用户态 |
| 故障隔离 | 服务崩溃不影响内核 |
| 实时优先 | 调度和中断处理考虑实时性 |
| 全新设计 | 从零构建（Clean-slate），不依赖传统 OS 架构 |
| 可验证性 | 设计时考虑形式化验证潜力 |
| 混合语言 | 内核 C 语言（MISRA C:2012 合规），用户态服务可选 Rust |
