## VirtIO Block 驱动开发 (08:38 - 10:56)

### 代码

  - 完整 VirtQueue 环形缓冲区管理
  - 描述符链构建 (hdr → data → resp)
  - 同步轮询模式读写
  - Legacy (v1) PFN 寄存器支持
  - 自动扫描 32 个 MMIO slot

### 实现细节

#### VirtQueue 内存布局 (静态分配)
```
vq_mem[~4KB] (4096 对齐)
├── desc_table[8] × 16 bytes = 128 bytes
├── avail_ring (hdr + ring[8] + event) = ~22 bytes
├── (padding to 4-byte align)
└── used_ring (hdr + elem[8] + event) = ~70 bytes
```

#### 描述符链 (3 段)
```
desc[0]: req_hdr (设备只读, F_NEXT)
desc[1]: data (读=F_NEXT|F_WRITE, 写=F_NEXT)
desc[2]: resp (设备可写, F_WRITE)
```

#### 设备自动发现
```c
// 扫描 0x0A000000..0x0A003E00 (32 slots × 0x200)
// 找到 magic=0x74726976 且 device_id=2 的 slot
```

### QEMU 验证结果

### 未解决: virtqueue 设备无响应
- **现象**: 提交请求到 available ring + QUEUE_NOTIFY 后，used ring idx 不变
- **已尝试**: Modern (DESC_LOW/HIGH) → 失败, Legacy (QUEUE_PFN) → 仍失败
- **待验证**: PFN 地址格式、DMA 物理地址映射、描述符链 addr 字段

### 关键技术发现

1. **QEMU virtio-mmio slot 分配不固定**
   - virtio-blk-device 被分配到 slot=31 (0x0A003C00), 不是 slot=0
   - 必须扫描才能找到设备地址

2. **VirtIO MMIO Legacy vs Modern**
   - QEMU virt 报告 version=1 (Legacy)
   - Legacy 使用 QUEUE_PFN (0x040) 传递物理页帧号
   - Modern 使用 DESC_LOW/HIGH (0x080/0x084) 传递 64 位地址
   - Legacy 不支持 QUEUE_READY 寄存器

3. **device_id 时序问题**
   - probe 期间 device_id=0
   - 扫描循环中 device_id=2
   - 原因未确定（可能与设备初始化时序有关）
