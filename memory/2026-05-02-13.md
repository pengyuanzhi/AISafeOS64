## 架构设计

### 1. 核心原理

**零拷贝消息传递** 采用以下原理：
1. **共享内存区域**：使用共享内存区域存储消息
2. **引用计数**：管理共享内存的生命周期
3. **零拷贝发送**：直接引用共享内存中的数据
4. **零拷贝接收**：接收方直接访问共享内存中的数据

### 2. 数据结构

**消息头（存储在共享内存中）**：
- state: 消息状态（空闲/使用中）
- src: 源线程 ID
- dst: 目标线程 ID
- size: 消息大小
- ref_cnt: 引用计数
- msg_id: 消息 ID
- flags: 消息标志

**消息缓冲区（缓存行对齐）**：
- header: 消息头
- data: 消息数据（4KB）

**共享内存区域（缓存行对齐）**：
- msgs: 消息数组（1024 个）
- free_count: 空闲消息数量
- used_count: 已使用消息数量
- next_msg_id: 下一个消息 ID
- lock: 区域锁
- region_id: 区域 ID

**零拷贝管理器（缓存行对齐）**：
- regions: 共享内存区域数组（4 个）
- total_free: 总空闲消息数量
- total_sends: 总发送次数
- total_receives: 总接收次数
- total_copies: 总拷贝次数

### 3. 关键算法

#### 零拷贝发送算法
1. 查找空闲消息槽位（遍历所有区域）
2. 加锁
3. 复制数据到共享内存
4. 设置消息头（状态、源、目标、大小、引用计数）
5. 更新统计信息
6. 解锁

#### 零拷贝接收算法
1. 查找指定源线程的消息（遍历所有区域）
2. 加锁
3. 直接访问共享内存中的数据（零拷贝）
4. 减少引用计数
5. 如果引用计数为 0，标记为空闲
6. 更新统计信息
7. 解锁

#### 引用计数管理
1. 发送消息时，引用计数设为 1
2. 接收消息时，引用计数减 1
3. 释放消息时，引用计数减 1
4. 如果引用计数为 0，标记为空闲

### 4. 性能特点

**优点**：
- ✅ 零拷贝，直接访问共享内存
- ✅ 减少内存拷贝开销
- ✅ 减少内存带宽压力
- ✅ 提高消息传递速度
- ✅ 缓存行对齐，减少缓存行争用

**缺点**：
- ⚠️ 共享内存需要额外内存
- ⚠️ 引用计数管理复杂度较高
- ⚠️ 需要手动管理消息生命周期

## 使用示例

### 初始化零拷贝管理器
```c
zero_copy_manager_t manager;

/* 初始化零拷贝管理器（4 个共享内存区域）*/
zero_copy_init(&manager, 4);
```

### 零拷贝发送消息
```c
const char *data = "Hello, Zero Copy!";
uint32_t size = strlen(data) + 1U;
uint32_t msg_id;

/* 零拷贝发送消息，不进行数据拷贝 */
zero_copy_send(&manager, dst_thread_id,
               data, size, &msg_id);
```

### 零拷贝接收消息
```c
const void *msg_data;
uint32_t msg_size;
uint32_t msg_id;
uint32_t flags;

/* 零拷贝接收消息，直接访问共享内存中的数据 */
if (zero_copy_receive(&manager, src_thread_id,
                      &msg_data, &msg_size,
                      &msg_id, &flags) == KERNEL_OK)
{
    /* 直接处理消息数据，不需要拷贝 */
    process_message(msg_data, msg_size);
}
```

### 释放消息
```c
/* 释放消息，减少引用计数 */
zero_copy_release(&manager, msg_id);
```

### 增加引用计数
```c
/* 增加引用计数，防止消息被过早释放 */
zero_copy_ref(&manager, msg_id);
```

### 获取统计信息
```c
uint64_t total_sends, total_receives, total_copies;
uint32_t total_free;

zero_copy_get_stats(&manager,
                   &total_sends,
                   &total_receives,
                   &total_copies,
                   &total_free);
```

## 风险评估

### 技术风险
- **引用计数错误**：可能导致内存泄漏或过早释放
  - 缓解措施：充分的测试，边界条件测试
- **共享内存竞争**：多线程访问共享内存可能导致竞争
  - 缓解措施：使用锁保护共享内存访问
- **内存泄漏**：消息未正确释放可能导致内存泄漏
  - 缓解措施：引用计数管理，测试验证
