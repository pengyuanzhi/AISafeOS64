# SMP 优化 - 分片锁、IPI 优化计划

## 优化目标

1. **锁竞争优化（分片锁）**
   - 将全局锁改为分片锁，减少锁竞争
   - 添加分片选择策略，提高分布均匀性
   - 优化锁的粒度，减少临界区

2. **IPI 优化**
   - 优化 IPI 发送和接收机制
   - 添加 IPI Coalescing（批处理），减少 IPI 数量
   - 优化 IPI 延迟和吞吐量

## 1. 锁竞争优化（分片锁）

### 1.1 分片锁设计

**场景**：当前某些数据结构使用全局锁（如 s_vma_pool_lock），在多核环境下容易成为性能瓶颈。

**解决方案**：将全局锁改为分片锁，每个分片独立管理一部分数据，减少锁竞争。

**分片锁接口**：
```c
typedef struct {
    uint32_t lock_num;           /* 分片锁数量 */
    TicketLock_t *shards;       /* 分片锁数组 */
} ShardedLock_t;

/* 初始化分片锁 */
kernel_status_t sharded_lock_init(ShardedLock_t *slock, uint32_t num_shards);

/* 销毁分片锁 */
void sharded_lock_destroy(ShardedLock_t *slock);

/* 根据键值选择分片 */
static inline uint32_t sharded_lock_select(const ShardedLock_t *slock, const void *key);

/* 获取指定分片的锁 */
static inline void sharded_lock_acquire_shard(ShardedLock_t *slock, uint32_t shard_id);

/* 释放指定分片的锁 */
static inline void sharded_lock_release_shard(ShardedLock_t *slock, uint32_t shard_id);

/* 根据键值获取对应的分片锁 */
static inline void sharded_lock_acquire(ShardedLock_t *slock, const void *key);

/* 根据键值释放对应的分片锁 */
static inline void sharded_lock_release(ShardedLock_t *slock, const void *key);
```

**应用场景**：
- VMA 池锁：分片锁管理，每个分片管理一部分 VMA
- 能力表锁：分片锁管理，每个分片管理一部分能力
- 线程池锁：分片锁管理，每个分片管理一部分线程

### 1.2 分片选择策略

**策略 1：简单哈希分片**
```c
static inline uint32_t sharded_lock_select_simple(const ShardedLock_t *slock, const void *key)
{
    /* 使用指针的高位作为哈希输入，保证均匀分布 */
    uint64_t key_hash = (uint64_t)key;
    uint32_t shard_idx = (uint32_t)((key_hash >> (64U - shift_bits)) & (slock->num_shards - 1U));
    return shard_idx;
}
```

**策略 2：改进哈希分片**
```c
static inline uint32_t sharded_lock_select_improved(const ShardedLock_t *slock, const void *key)
{
    /* 改进的哈希：混合高位和低位，减少哈希冲突 */
    uint64_t key_hash = (uint64_t)key ^ ((uint64_t)key >> 32U);
    uint32_t shard_idx = (uint32_t)((key_hash >> (64U - shift_bits)) & (slock->num_shards - 1U));
    return shard_idx;
}
```

## 2. IPI 优化

### 2.1 IPI Coalescing（批处理）

**场景**：当前每次 IPI 都立即发送，可能导致 IPI 洪水，降低性能。

**解决方案**：实现 IPI Coalescing，将多个 IPI 合并为一次发送，减少 IPI 数量和开销。

**IPI Coalescing 接口**：
```c
typedef enum
{
    IPI_COALESCE_STATE_IDLE = 0U,        /**< @brief 空闲：无待处理 IPI */
    IPI_COALESCE_STATE_COLLECTING,    /**< @brief 收集：正在收集待处理 IPI */
    IPI_COALESCE_STATE_SENDING,       /**< @brief 发送：正在批量发送 IPI */
    IPI_COALESCE_STATE_WAITING,        /**< @brief 等待：等待发送完成 */
} ipi_coalesce_state_t;

typedef struct
{
    ipi_coalesce_entry_t entries[IPI_COALESCE_MAX_BATCH]; /**< @brief IPI 条目数组 */
    uint32_t                count;                            /**< @brief 当前条目数量 */
    ipi_coalesce_state_t    state;                            /**< @brief 当前状态 */
    TicketLock_t            lock;                             /**< @brief 批处理器锁 */
} ipi_coalesce_t;

/* IPI Coalescing 初始化 */
kernel_status_t ipi_coalesce_init(void);

/* 尝试添加 IPI 到批处理器 */
bool ipi_coalesce_try_add(uint32_t target_cpu, ipi_type_t type, void *arg);

/* 立即发送 IPI（绕过批处理） */
void ipi_coalesce_send_immediate(uint32_t target_cpu, ipi_type_t type, void *arg);

/* IPI Coalescing 定时器处理 */
void ipi_coalesce_timer_handler(void);
```

### 2.2 IPI 延迟优化

**场景**：当前 IPI 延迟可能较高，影响 SMP 性能。

**解决方案**：优化 IPI 发送和接收路径，减少 IPI 延迟。

**优化策略**：
```c
/* 优化 IPI 发送路径 */
void ipi_send_optimized(uint32_t target_cpu, ipi_type_t type)
{
    /* 直接写入 GIC 寄存器，减少中间层 */
    gic_sgi_send(target_cpu, type);
    
    /* 使用 DSB 确保写入完成 */
    hal_dsb_sy();
}
```

## 6. 风险评估

### 6.1 技术风险

- **复杂性风险**：分片锁和 IPI Coalescing 增加系统复杂性
- **正确性风险**：缓存一致性协议容易出错，需要充分测试
- **性能风险**：优化可能带来意外的性能下降

### 6.2 缓解措施

- **渐进式实现**：分阶段实现，逐步验证
