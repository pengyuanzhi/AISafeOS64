## 完成工作

### 能力系统（CSpace）迁移到 Slab 分配器

将能力系统（CSpace）的能力表管理从静态数组迁移到 Slab 分配器，提高内存利用率和支持能力表的动态分配和回收。

**1. 能力表 Slab 缓存结构**

添加 `s_cap_table_slab` 结构到 cspace.c：
```c
static struct
{
    slab_cache_t caches[CSPACE_MAX_CAPACITY / 64U + 1U]; /**< 不同容量能力表的 Slab 缓存 */
    bool initialized;                                        /**< Slab 缓存初始化标志 */
} s_cap_table_slab;
```

**2. Slab 缓存初始化和销毁**

- `cspace_slab_init()`: 初始化能力表 Slab 缓存
  - 为不同容量能力表创建 Slab 缓存
  - 每个容量类别对应一个 Slab 缓存
  - 初始化失败时清理已创建的缓存

- `cspace_slab_destroy()`: 销毁能力表 Slab 缓存
  - 逐个释放所有 Slab 缓存
  - 清零结构体状态

**3. CSpace 能力表分配**

修改 `cspace_create()` 函数：
- 使用 `slab_alloc()` 从 Slab 缓存分配能力表
- 根据容量选择合适的 Slab 缓存
- 分配失败时回退到错误处理逻辑
- 初始化能力表为空

**4. 能力表释放**

修改 `cspace_destroy()` 函数：
- 使用 `slab_free()` 释放能力表回 Slab 缓存
- 释放前检查指针有效性
- 清空能力表指针

**5. 头文件依赖修复**

- 修改 `slab.h`: 移除多余的 `<kernel/kernel.h>` 包含
- 修改 `cspace.c`: 移除不存在的 `<kernel/mm/kmalloc.h>` 包含

### 技术特点

1. **动态分配**: CSpace 能力表现在动态分配，支持可变容量
2. **内存回收**: CSpace 销毁后能力表现在可被回收重用
3. **分层策略**: Slab 分配器 + 静态池混合策略
4. **安全清理**: 释放前完整清理能力表状态
5. **向后兼容**: CSpace API 不变，内部实现优化

### 内存优化效果

| 指标 | 优化前 | 优化后 | 改进 |
|------|--------|--------|------|
| 内存利用率 | 静态分配不可回收 | 可动态回收重用 | ✅ 显著提升 |
| 灵活性 | 固定容量 | 可变容量 | ✅ 更灵活 |
| 碎片化 | 高（固定容量） | 低（Slab 分配） | ✅ 降低碎片 |
| 扩展性 | 固定（CONFIG_MAX_CSPACES） | 动态（Slab 池） | ✅ 更灵活 |
