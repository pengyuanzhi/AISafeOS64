## 架构设计

### 1. 核心原理

**Per-CPU 内存池** 采用以下原理：
1. **Per-CPU 分配**：每个 CPU 有独立的内存池（64KB）
2. **减少锁竞争**：不需要全局锁，每 CPU 独立管理
3. **快速分配**：直接从本地池分配，减少跨核访问
4. **平衡机制**：当某 CPU 池不足时，从其他 CPU 池借用
5. **与 Slab 配合**：per-CPU 内存池与 Slab 缓存配合使用

### 2. 数据结构

**Per-CPU 块（块节点）**：
- 状态：空闲或已分配
- 数据区域：128 字节
- 分配次数：该块的分配次数
- 释放次数：该块的释放次数

**Per-CPU 内存池**：
- blocks 数组：所有块节点（512 个）
- free_count：空闲块数
- allocated_count：已分配块数
- total_allocations：总分配次数
- total_frees：总释放次数
- borrow_count：借用次数
- lend_count：借出次数

**Per-CPU 内存池系统**：
- pools 数组：所有 CPU 的内存池
- total_size：总大小
- total_free：总空闲块数
- total_allocated：总已分配块数
- balance_count：平衡次数

### 3. 关键算法

#### 内存分配算法
1. 从本地 CPU 内存池查找空闲块
2. 如果找到，直接分配
3. 如果没找到，从其他 CPU 池借用
4. 更新统计信息

#### 内存释放算法
1. 根据指针找到块索引
2. 标记块为空闲
3. 更新统计信息

#### 平衡算法
1. 找到需要借用的 CPU（空闲块 < 阈值）
2. 找到可以借出的 CPU（空闲块 > 阈值）
3. 转移块所有权
4. 更新统计信息

### 4. 性能特点

**优点**：
- ✅ 减少锁竞争，每 CPU 独立管理
- ✅ 快速分配，直接从本地池分配
- ✅ 减少跨核访问，提高缓存命中率
- ✅ 自动平衡，从其他 CPU 池借用

**缺点**：
- ⚠️ 内存浪费，每个 CPU 64KB
- ⚠️ 平衡开销，需要定期平衡
- ⚠️ 复杂度较高

## 使用示例

### 初始化 Per-CPU 内存池系统
```c
per_cpu_pool_system_t sys;

/* 初始化 Per-CPU 内存池系统（4 个 CPU，每个 64KB）*/
per_cpu_pool_system_init(&sys, PER_CPU_POOL_SIZE * 4);
```

### 分配内存
```c
/* 分配 128 字节内存 */
void *ptr = per_cpu_pool_alloc(&sys, 128);
```

### 释放内存
```c
/* 释放 128 字节内存 */
per_cpu_pool_free(&sys, ptr, 128);
```

### 平衡 Per-CPU 内存池
```c
/* 平衡 Per-CPU 内存池 */
per_cpu_pool_balance(&sys);
```

### 获取统计信息
```c
uint32_t free_count, allocated_count, borrow_count, lend_count;
uint64_t total_allocations, total_frees;

per_cpu_pool_get_stats(&sys, 0,
                       &free_count,
                       &allocated_count,
                       &total_allocations,
                       &total_frees,
                       &borrow_count,
                       &lend_count);
```

## 风险评估

### 技术风险
- **内存浪费**：每个 CPU 64KB，可能浪费内存
  - 缓解措施：可调整内存池大小
- **平衡开销**：定期平衡可能增加开销
  - 缓解措施：异步平衡，减少影响
- **借用机制**：借用可能导致块所有权复杂
  - 缓解措施：优化借用算法，减少借用次数
