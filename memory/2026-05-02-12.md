## 架构设计

### 1. 核心原理

**消息队列分片锁** 采用以下原理：
1. **分片锁**：将消息队列分成多个分片，每个分片独立管理一部分消息
2. **减少锁竞争**：不同 CPU 可以并发访问不同的分片
3. **自动切换**：当当前分片已满时，自动切换到下一组分片
4. **负载均衡**：读写分片轮流使用不同分片

### 2. 数据结构

**消息队列分片（块节点）**：
- messages 数组：所有消息节点（128 个）
- write_idx：写入索引
- read_idx：读取索引
- msg_count：消息数量
- total_enqueues：总入队次数
- total_dequeues：总出队次数
- lock：分片锁

**消息队列分片锁（根结构）**：
- shards 数组：所有分片节点（4 个）
- write_shard_idx：当前写入分片索引
- read_shard_idx：当前读取分片索引
- switch_count：分片切换次数
- total_enqueues：总入队次数
- total_dequeues：总出队次数
- max_msg_count：最大消息数量

### 3. 关键算法

#### 入队算法
1. 获取当前写入分片
2. 检查分片是否已满
3. 如果已满，切换到下一组分片
4. 加锁并写入消息
5. 更新统计信息

#### 出队算法
1. 获取当前读取分片
2. 查找非空分片
3. 如果当前分片为空，切换到下一组分片
4. 加锁并读取消息
5. 更新统计信息

#### 分片切换算法
1. 计算下一组分片索引：(当前索引 + 1) % 分片数量
2. 更新写入/读取分片索引
3. 增加分片切换次数

### 4. 性能特点

**优点**：
- ✅ 减少锁竞争，不同分片可以并发访问
- ✅ 提高并发性能，支持多线程并发入队/出队
- ✅ 自动负载均衡，读写分片轮流使用
- ✅ 缓存行对齐，减少缓存行争用

**缺点**：
- ⚠️ 需要额外的内存开销（多个分片）
- ⚠️ 分片切换可能增加延迟
- ⚠️ 复杂度较高

## 使用示例

### 初始化消息队列分片锁
```c
sharded_mq_t mq;

/* 初始化消息队列分片锁 */
sharded_mq_init(&mq);
```

### 入队消息
```c
sharded_mq_msg_t msg;

msg.type = SHARDED_MQ_MSG_NORMAL;
msg.size = sizeof(data);
msg.data = data;
msg.src_thread = src_tid;
msg.dst_thread = dst_tid;
msg.status = 0;

sharded_mq_enqueue(&mq, &msg);
```

### 出队消息
```c
sharded_mq_msg_t msg;

int ret = sharded_mq_dequeue(&mq, &msg);

if (ret == KERNEL_OK)
{
    /* 处理消息 */
    process_message(&msg);
}
else
{
    /* 队列为空 */
}
```

### 检查队列是否为空
```c
if (sharded_mq_is_empty(&mq))
{
    /* 队列为空 */
}
```

### 获取统计信息
```c
uint32_t total_msgs;
uint64_t total_enqueues, total_dequeues;
uint32_t switch_count;

sharded_mq_get_stats(&mq,
                       &total_msgs,
                       &total_enqueues,
                       &total_dequeues,
                       &switch_count);
```
